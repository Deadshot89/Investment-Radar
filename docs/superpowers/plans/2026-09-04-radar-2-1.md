# Radar 2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expand the production Radar to at least 2,000 Trade-Republic-verified stocks/ETFs, fix ETF purchase eligibility, make the buy filter exact, and expose result counters in Android.

**Architecture:** Build a balanced Trade Republic catalog and universe, then cache analyzed summaries server-side so recommendation filters operate on a stable snapshot instead of rescoring thousands of instruments per request. Add ETF-specific scoring proxies compatible with available external ETF data, then surface backend counters in the Android Radar UI.

**Tech Stack:** Node.js backend modules/tests, Kotlin/Jetpack Compose Android app, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-04-radar-2-1.md`

## Global Constraints
- Minimum production universe: 2,000 active Trade-Republic-verified instruments.
- BUY score threshold stays 75.
- `KAUFEN` must imply `purchaseEligible=true`.
- Unverified instruments must never become buy candidates.
- Android release target: versionName `2.1.0`, versionCode `53`.
- No automatic order execution.
